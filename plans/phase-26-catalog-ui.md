# Phase 26 — Catalog UI review

> Order 3 in the [active queue](README.md). Timebox to defects found in review. The cut catalog
> sidebar (static project-summary panel) stays cut.

## Scope and boundaries

Review the catalog list, filters, empty state, cards, detail pages and creator return. Fix
current UI issues that make the catalog look unfinished or break the path into the creator.
Do not add catalog features, new SKUs, a project-summary sidebar or a product-asset production
pass.

Keep product dimensions and validation independent of visuals. Catalog photos already cover the
active set; this phase is presentation and interaction, not new imagery unless a specific UI
defect requires a crop or alt-text fix.

## Remaining outcome

- Catalog browsing, filtering, empty state, product cards and detail pages are acceptable for
  submission.
- Known UI defects found in this review are fixed or explicitly deferred.
- Creator return and catalog WebMCP tools still share the same project model.

## Work sequence

1. Walk the catalog as a judge would: filters, empty state, a representative card, a detail page
   and return to the creator.
2. Apply only the UI fixes justified by that review.
3. Re-check the same path after the fixes.

## Exit gate

The catalog is good enough to leave alone unless a later premium-look pass still has time, or
submission verification finds a real defect. Transfer durable catalog UI decisions into the
relevant docs, then remove this plan and its index row.
